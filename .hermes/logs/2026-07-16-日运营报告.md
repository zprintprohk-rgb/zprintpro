## 🧠 Memory 教訓 (v4 階段,可寫入跨項目 memory)

### 1. LongDescription template literal 內部不能信任何子串
- Next.js 14 product object 有 `longDescription: \`<h3>...</h3>\n<table>...</table>\`` 字段,內含大量 HTML markup
- 任何 `find('slug: \'', ...)`, `find('},', ...)`, `find('minQuantity', ...)` 都可能撞到 longDescription 內的子串
- **balance tracking 必須 template-literal aware**:遇到 backtick 進入 template state,跳過所有 `{}` 計數,直到下一個 backtick
- 或者:用 unique multi-line anchor (e.g. `minQuantity: 100,\n    images: ['/images/products/a4-flyers.jpg']`) 精準定位

### 2. TS1117 duplicate property 警示
- 在 add `optimizedAt` / `optimizationRound` 之前,必須先嚴格 verify「真的沒有」
- 即使先 inspect 顯示 ABSENT,可能是 balance tracking 誤判
- 修法:用 file position L2144 直接讀 line content 比對,或用 unique multi-line anchor 找最近的 metadata 字段
- 如果失敗,git restore + 跳過,絕不盲目 add

### 3. description_zh regex `([^']+)` 不可靠
- 假設 description_zh 字符串內不含 `'`,但 longDescription 的 opening backtick 之前的 `, \n  longDescription: \`...` 也含 `,`,雖然不含 `'`,但**長 description 字符串 + 緊接 backtick** 容易讓 regex 跨過邊界
- 修法: 用 `text.find(old_string)` 找 anchor,然後 `text.replace(old_string, new_string, 1)`,不用 regex offset 計算

### 4. cron pre-check 順序
- 先 `node scripts/check-encoding.js --fix` (encoding)
- 再 `git add` (selective, 不用 `git add .`)
- 然後 `npm run build` (本地驗證)
- 最後 `git commit + git push`
- 跳過任何一步 = build 風險

### 5. next.js 14 product 路由是單數 `/product/` 不是 `/products/`
- 所有 8 locale 14 internal links 全 200 用的是 `/product/` 單數
- 之前的 `/products/` 308 → 404 是 curl 工具路徑錯位,不是 prod 錯

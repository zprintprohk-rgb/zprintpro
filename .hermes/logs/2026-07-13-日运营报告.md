**Root cause**: Write 工具 + Bash 工具在 session 多次 write 后被限流,只能靠 Edit 工具 (small oldString + small newString) 完成微小修改。

**教训 (跨项目,需写 memory)**:
- 写大量 HTML content 到 src/data/blog-data/*.json 时,**单次 Python 脚本**是最稳路径(per memory §7 escape SOP)
- **多文件 Python 脚本同时写 3 locale**比 **拆成 3 个单 locale 脚本**更稳(避免 Write 工具反复 blocked)
- Edit 工具 large newString (>5KB) 不可靠,**大 content 必须用 Python 全量重写文件**
- 写多 locale blog 时,**先 1 个 locale 跑通,再扩到 3 locale** 比一次写 3 locale 失败再 retry 更稳
- PowerShell heredoc 写 .html 文件**有效**,但 Bash 工具在多次大写后会被 blocked
- **PARTIAL DELIVERY 是正确选择** — 不"卡住硬撑",已 done 的 Blog #1 优先上线,Blog #2 zh 内容已写,下次 cron 续 en/ja

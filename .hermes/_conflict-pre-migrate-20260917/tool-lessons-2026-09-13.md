# 工具教训 · PowerShell 编码导致 3 次误判（2026-09-13）

> 记录人：deepseek hermes（主审计员）｜触发：一天内因**测量工具**误判 3 次，其中 2 次已对外发布结论
> 建议：下一轮把「硬规则」写进 AGENTS.md（属执行纪律，需 K3 一句话）

## 一、事实经过（我错了什么）

| # | 我发布的结论 | 实际 | 被谁纠正 |
|---|---|---|---|
| 1 | 「B 报的 69 处双品牌**无法复现**，先不采信」 | **B 是对的**：69 处确实存在 | 我随后量了回归版才发现（此前量的是修复后版本） |
| 2 | 「回滚后那 2 个名片 SKU 本身就是名片语义」 | **错的**：回滚确实把它们退回「賀卡」 | 线上 title 实测（`400g 超厚賀卡印刷`） |
| 3 | 「`csv-to-sku-seo.mjs` **自带双品牌兜底模板**，是复发之源」 | **错的**：生成器 L49-51/L82 只是从 CSV 原样复制，**完全无辜**；双品牌在 CSV 的 title 单元格里 | Node utf-8 读出 CSV 有 345 处「智印港」、69 行同行 |

## 二、根因（已实测定位）

**Windows PowerShell 5.1 的 `Get-Content` / `Select-String` 对无 BOM 的 UTF-8 文件默认按 ANSI(GBK) 解码** → 中文变乱码，**只有 ASCII 串能命中**。

铁证（同一文件、同一时刻）：

| 工具 | 搜「智印港」 | 搜 `ZprintPro` |
|---|---|---|
| PowerShell `Get-Content -Raw` + `[regex]::Matches` | **0** ❌ | 628 ✓ |
| Node `fs.readFileSync(csv,'utf8')` | **345** ✓ | 628 ✓ |

附带两个坑：
1. `git show X:file > dump.txt` 用 PS 重定向 → 写出非 UTF-8 → Node 读回 **0 命中**（造成二次误判）
2. 控制台乱码会误导人工判读：`璩€鍗?`=賀卡、`鍚嶇墖`=名片、`鏅哄嵃娓?`=智印港

## 三、硬规则（建议纳入执行纪律）

1. **任何 CJK 计数/匹配，一律用 Node 或 Python 以 `utf8` 读取**；禁止用 PowerShell `Get-Content`/`Select-String` 做中文判定
2. 需把 git 内容交给 Node 分析时，**不要用 `>` 重定向**；改为 Node 内 `execFileSync`（注意沙箱下 piped stdio 可能 EPERM）或先用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`
3. **判定"某串不存在"前，必须两种独立工具交叉验证**——今天 3 次误判全部源于"单一工具 + 单一时点"下结论
4. **比较两个版本时，先确认对照基准**（我第 1 次误判就是拿"修复后"去否定别人量的"回归版"）
5. 报告中的乱码一律不作人工判断依据，需按**码点**复核

## 四、这条教训的正向价值

同样是这套方法，今天也带来了正确的关键发现：
- 定位到 `202e7698` 的真实回归规模（keys 700→525、titles 300→225、24 个 SKU 丢 SEO）
- 用码点验证出双品牌的分隔符是**普通空格(32)**，排除了"隐藏字符"假设
- 证明**生成器无辜**，从而避免了一次错误的"禁跑脚本"决策（否则会砍掉 SOP-5 流水线）

## 二、硬规则（追加到 §三 之后）

1. **lane 环境的工具面 ≠ 交互会话的工具面**：dsh headless lane 沙箱 pwsh 被禁。任何给 lane agent 的 prompt 必须**显式声明工具边界**（哪些可用/哪些禁），禁止让 agent 靠试错发现——试错成本是墙钟时间，撞守护即整轮失败。
2. **守护上限按车道真实负载校准**：gsc 完整流程（读 11,000+ 行 matrix + 对比 + 回灌 + 报告）实测 >1800s；统一按 heavy lanes 3600s 设，不按"看起来轻"猜。
3. **环境注记固化进 wrapper 生成器**：`scripts/register-cron-tasks.ps1` 内嵌注记文本，重注册即全量带上，避免手改遗漏。

## 三、正向价值

- 轮 2 证明全链路可用：触发链（guard→cmd→dsh headless→agent→报告/矩阵落盘→exit 0）。

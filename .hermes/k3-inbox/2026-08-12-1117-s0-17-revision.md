## §1 完整规则 (修订后)

### §1.1 基础限制
- 1 天 ≤ 5 push (基础线)
- 1 月 ≤ 150 CF build (单项目, 3 项目共享 500/月 账户)
- amend 1 月 ≤ 2 次 (8/8 117f9fc + 8/10 8664488 已用满)
- force-push 也算 1 push + 1 CF build
- cron auto push 不算手动 push (daily 10:15 / weekly 11:00 / monthly 1 号 / gsc 周三 15:00)

### §1.2 例外: 重要更新/优化 (🆕 K3 8/12 11:17 拍板)
- **触发条件**: 任一满足即视为"重要"
  - 🔴 P0 紧急修复 (5xx 阻断 / 死链 / 法律风险 / 安全漏洞)
  - 🟠 重要更新 (K3 战略层拍板 + 影响北极星 KPI / 品牌一致性 / GEO 实体 / 排名)
  - 🟡 优化 (类目 imps 加权 / 转化率 / 埋点修复, 跟主节奏捆绑)
- **不限量**: 重要更新/优化立即 push, 不受 5 push/天 限量
- **判定权**: M3 自判, 写进 commit message "K3 8/12 11:17 例外: <原因>"
- **报告**: 每日 EOD cron 报告里列"例外 push"清单, K3 复盘拍板 (默认通过, 有异议 K3 当晚驳回)

### §1.3 不属重要 (仍受 5/天 限制)
- typo / 单行注释调整 / 重构 / 测试代码 / 文档微调 / markdown 格式
- 不影响用户感知 / 业务指标 / 品牌一致性的纯技术改动

## §2 push 台账 SSoT (修订后)

| 字段 | 类型 | 说明 |
|---|---|---|
| date | YYYY-MM-DD | 推送日期 |
| commit_sha | 7 字符 | commit hash |
| push_type | code / docs / analytics / fix / feat | 类型 |
| is_important | 0 / 1 | 1 = §1.2 例外, 不限量 |
| reason | 短描述 | K3 拍板/战略层原因 |
| cf_run | GitHub Action ID | 验证用 |
| cf_status | success / failure / in_progress | 验证用 |
| month_count | 数字 | 月累计 push (含 force-push + amend) |
| month_remaining | 数字 | 月剩余 push |

**SSoT 路径**: `.hermes/push-ledger.csv` (git tracked, 8/13 起推首版)

## §4 反例 (K3 8/12 11:17 拍板的限制)

| 错误用法 | 为什么错 |
|---|---|
| ❌ "K3 拍板了例外" → 所有 push 都打"重要"标签 | 滥用, 跟没规则一样 |
| ❌ "我判断这个重要" → 没写进 commit message | 无法审计 |
| ❌ 重要 push 不报 K3 | K3 复盘看不到完整 push 流 |
| ❌ 例外 push 跑 build verification 5 步跳过 | 重要 = 风险高, 验证更严 |

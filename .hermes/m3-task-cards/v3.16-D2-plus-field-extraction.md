## Step 1 · 建 products-content.ts (脚本化, 禁手写)

写一次性脚本 `.hermes/_d2plus_extract.py`:
1. 读 `src/data/products.ts`
2. 对每个 SKU 对象, 提取 `longDescription` / `longDescriptionEn` / `longDescriptionJa` 三个字段的**原始文本** (含引号, 不重新序列化 — 避免转义差异)
3. 生成 `src/data/products-content.ts`:

```ts
// 长文本内容层 — 从 products.ts 物理搬移 (K3 v3.16 D2+)
// 仅 product/[slug] 与需要长文本的页面 import; 共享组件/列表/搜索不得 import 本文件
export const productsContent: Record<string, {
  longDescription?: string; longDescriptionEn?: string; longDescriptionJa?: string;
}> = {
  'premium-greeting-cards': { longDescription: ..., ... },
  ...
};
```

4. 同时输出 products.ts 的新版本: 删除这三字段 (其余字符一个不动)

## Step 2 · 修消费者 (tsc 报错驱动, 预计 2-5 个文件)

对每个 tsc 报错文件 (预期: `product/[slug]/page.tsx` 为主, 可能有 ProductTabs / category 页):
- 顶部加 `import { productsContent } from '@/data/products-content';`
- 用到长文本处改为 `productsContent[product.slug]?.longDescription` (或页面顶部合并: `const full = { ...product, ...productsContent[product.slug] };`)

**若某共享组件 (ProductCard/RelatedProducts/quote 组件) 报错** → 停手报 K3 (意味着长文本泄漏进了共享层, 需 K3 重新评估字段归属)。预期不会发生: K3 已抽查 ProductCard/RelatedProducts 只用轻字段。

## Step 3 · 体积验证 (二元化闸门)


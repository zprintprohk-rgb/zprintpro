三、error-patterns 入档 (追加, 0 删除)
  .hermes/regression-guard/error-patterns.md

  1. 规则 POWERSHELL_OUTPUT_ENCODING (K3 指定)
     - 事故: Tee-Object 落盘证据为 UTF-16LE(+FF FE BOM), git 判为 Bin,
             check-encoding 再报 CRLF 57 行 → 不可 diff/grep/review
     - 修法: 禁 PowerShell 重定向落盘文本; 用 fs.writeFileSync(p,c,'utf8') 并正规化 \r\n;
             落盘后自检三件 (无 BOM / 不出现 Bin / encoding exit 0)
     - 定位: METRIC_INTEGRITY_FIVE_TRAPS 第 7 种 (取证通道自身的编码陷阱)

  2. 观察记录 COMMIT_TIMESTAMP_ANOMALY (K3 指定, 🟡观察级, 未升级为规则)
     - 现象: 9330f96b 的 %ad=18:02:28 与首次读取时刻不一致
     - 排查: 无 amend / 无 reset / 无外来作者 / parent 正确 / 内容正确 → **未解释**
     - 判定: 最可能为取证时序 (commit 完成略晚于该次取证), 但未复现亦未证伪
     - 升级条件: 再现 1 次同类 → 升级为规则
     - 价值: 时间戳与直觉冲突时**先怀疑取证时序**, 不要直接怀疑仓库被篡改

  3. 规则 SELF_REPORT_METRIC_DISAGREEMENT (本轮新增, 根因定案)
     - 事故: 手打字符串经 node -e 传给 equiv() 得 46, 文件实测同行得 49, **稳定差 3**
     - 初判: 极易误判为「当量函数对 $ / + 处理有 bug」
     - 真相: **PowerShell 双引号内 $99 被变量展开**, 传入的根本不是文件里的字符串;
             改用从文件读取后, 与 verify-menus.cjs 逐字一致
     - 判据: **稳定偏移 ≠ 必然工具 bug**; 更常见的是**输入通道确定性改写**
     - 修法: 凡复算文件里的值必须从文件读; 两法不一致时**先 dump 输入**(len + 码位)
             而非怀疑量具; 双方法复算必须**同定义域**

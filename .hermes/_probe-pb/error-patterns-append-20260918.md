# 门禁盲区三例 · 2026-09-18 固化（K3 要求写入 error-patterns.md 作为 DoD 铁律输入）

> 来源：队列 A #3 寫真書交付验收（线上探针）+ 队列 P0 第 2 篇 Self-Publishing 交付（三语线上探针）。
> 共同教训（已在 §0.23.1 固化过一次，本轮再添三例）：**门童 0 命中 ≠ 线上干净**。

## 盲区 1 — `@ts-nocheck` 让 tsc 门禁对整文件完全失效

**现象**：线上 201 个 HTTP200 博客页中 **124 个没有 `<meta name="description">`**；根因是
`src/app/[locale]/blog/[slug]/page.tsx:820` 读取 `meta?.description?.[locale]`，而 `BlogPostMeta`
的字段名是 **`excerpt`**（`src/data/blog-posts.ts:53`，全仓 100 条 meta 全用 `excerpt`，`description` 0 条）。

**为何存活**：`page.tsx` **L1 就是 `// @ts-nocheck`** ⇒ 该类型错误被整文件吞掉；而验收线是
「**tsc 54 = 54 持平**」—— 这条线恰好把真缺陷一起「持平」掉了。

**固化**：① 门童 #20 新增**规则 D `META_DESCRIPTION_RENDER_PATH`**（D1 禁读不存在字段；
D2 描述解析必须引用真实来源）；② 该文件改动**必须加 esbuild 语法校验**（`@ts-nocheck` 不豁免语法错误，
但语法闸门不可依赖 tsc 报告）；③ 「tsc 持平」不可作为唯一类型防线，须配合源码结构断言。

## 盲区 2 — 门童 #4 跨语言污染规则**只单向**（只查 zh-hk）

**现象**：`src/lib/price-data.generated.ts` 中 **18 个 SKU / 342 个栏位**语言污染：
en/ja 键位含中文（252 栏位）、**zh-hk 键位含简体字 90 栏位**。根因是生成器
`scripts/gen-price-data.mjs` 把同一源头串写进三个语系键位：
`label: { 'zh-hk': cfg.config, en: cfg.config, ja: cfg.config }`（cfg.config 为简体的供应商原始标签）。

**为何存活**：门童 #4 的调用是 `scanLocaleScoped(content, file, pollution, ['zh-hk'])` —— **只检查
「zh-hk 里混入英/日」这一个方向**；「en/ja 里含 CJK」「zh-hk 里含简体」两个方向**从未被检查**。

**固化（设计结论，已实测验证，务必照此否则会变成死守卫）**：
- **en 含 CJK** → 恒为缺陷（英文不需要中文），零误报，可直接上；
- **ja** → 「含 CJK」**无意义**（日文本就用汉字）；判据应为「含**简体专用字形**」，且**必须排除日文新字体**
  （写/数/点/双/学/画/国 等 —— 实测：把 `写` 判为简体即误报，因 `写真` 是日文正确写法）；
- **zh-hk** → 判据为「含**简体专用字形**」。
- **字集必须 curate**：只收「繁体必与简体不同形」者。反例（2026-09-18 实测踩中）：
  把「進出／費用／計算／條件」拆成单字整批入集，导致 **出/算/用/件** 被误判（四者皆**繁简同形**）。
- **必须配专用基线通道**（比照门童 #20 的 `.hermes/meta-baseline.json`：录入 342 处存量、**只许递减**），
  否则 red 会由 51 爆到 300+ 直接拦死全站 commit；反之字集不收窄则假阳性泛滥 → 沦为无人理会的死守卫。
- 新增规则须附**假缺陷注入回放测试**：注入「en 含中文」→ 必报红；空跑 → 基线与 red 51 不变。

## 盲区 3 — `scan-simplified.mjs` 覆盖面不足

**现象**：该扫描器报「**所有 zh-hk 产品名称都是纯繁体中文**」的同时，`price-data.generated.ts` 有
**90 处 zh-hk 简体栏位**、`src/components/seo/GeoFooterText.tsx:19-22` 的 **zh-hk 页脚整段是简体**
（⇒ **全站每一个 zh-hk 页面**都可见）。

**为何存活**：该扫描器**不覆盖** `src/components/` 与 `price-data.generated.ts`。

**固化**：简体扫描范围须与「客户可见文本」范围对齐（组件 + 生成数据 + blog-data + messages），
并纳入盲区 2 的三语系分语系字集规则（不要另立一套口径）。

## 附带教训 — 探针归因纪律（本轮两次自查纠错）

1. **不要直接采信自己探针的「FAIL」**：首版探针把**站点 footer** 的简体误判成本次交付缺陷。
   正确做法 = **与对照页取集合差**（取一篇早前已交付且已知干净的同类页作 chrome 基线）：
   `本文页简体集合 − chrome 基线 = 本次交付引入量`（修正后本次交付引入量 = 0）。
2. **量测正则不可贪婪**：数字比对用了「数字后接任意数字/逗号/句点」，把句尾句点一起吃进去，
   使 `US$207.94.` ≠ `207.94` → 误报「新造数字」。必须剥除尾随标点。

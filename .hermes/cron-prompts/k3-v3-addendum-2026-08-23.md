## §A 2 · K3 5 SOP 完整谱系 (2026-08-22 17:58 + 8/22 23:00 + 8/23 02:52 K3 拍板)

### SOP-1 红灯冻结令 (治 P1 纪律问题, 权重最高)

**触发**: verify-deploy 返回 failure / curl 5 连出现 5xx 或 404 / 线上 schema 解析失败

**动作**:
- 停止一切编辑与 push, 含"和失败无关"的任务
- 唯一允许: ① 根因调查 (只读) ② 1 段报告 K3 ③ 等拍板
- 收到拍板后只允许执行拍板内容本身, **不允许"顺手带"其他任务上同一班车**

**自检句式** (每次 push 前默念): "上一次 verify 是绿的吗?"

**cron 应用**: 4 cron 任一执行中出现 build FAIL / curl 5xx → 立即停手, 1 段报告 K3

### SOP-2 阈值二元化 (治 P2 虚报)

**表述规则**:
- 验收只有两种: `✅ 达标 (实测值 X ≥ 阈值 Y)` 或 `❌ 未达标 (实测值 X < 阈值 Y)`
- 禁"勉强达标 / 基本达标 / 差不多"

**单位混淆是验收无效**:
- 英文 snippet 阈值: 130-160 **词** ≈ 700-900 字符
- 中日文 snippet 阈值: 130-160 字 ≈ 200-280 字符
- chunk 大小: bytes vs KB vs MB 必标, gzip vs raw 必标

**未达标不是罪, 软化未达标才是罪**:
- 未达标 + 明确补救计划 = 不扣分
- 措辞掩盖 = 双倍扣分

**cron 应用**: 任何验收项 (snippet 字数 / 内链数 / GSC imps / Schema 覆盖率) 必用二元化表述

### SOP-3 根因 diff 优先法 (治 P3 机制猜测)

**第一动作**:
```bash
git show --stat <sha>
git diff <green-sha>..<fail-sha>   # 列全部结构差异
```

**结构差异清单** (按差异排序候选根因):
- 新 import
- 新目录
- 缺导出
- 配置文件改动 (next.config.js / wrangler.toml / package.json)
- 数据文件 schema 变化

**机制猜测只能排在结构差异之后, 且必须标注"未经 diff 排除" + 验证方法**

**cron 应用**: 任何 build 失败 / GSC 突降 / 收录异常 → 必先 diff, 禁纯机制猜测

### SOP-4 债务熔断 (治 P4 任务延后堆积)

**熔断规则**:
- 每版本最多延后 2 任务, 第 3 个 = 砍范围 (明确写"本版本不做"), 不写"延后"
- 同一任务连续 2 版本被延后 → 第 3 版本**强制第一优先执行**

**版本开工第一段**:
- 上版本债务清单
- 本版新增清单
- 熔断检查结论 (e.g. "T43 FAQPage JSON-LD 已达此线, v3.16 必须完成")

**cron 应用**: 4 cron 任一延后任务超过 2 周 → 必先做, 不允许"再延一周"

## 1. SOP-10 第 1 款 (K3 8/24 12:04 拍板 E)

> **派活前先查前序任务实现路径, 不推断"架构冲突"**

应用范围:
- 任何 worker 派活前, 用 `git show <commit> --stat` 看前序任务实现路径
- 任何"X 路径 vs Y 路径"判断, 先看 30 秒 git log, 不直接推断冲突
- 任何"前序任务未完成阻塞"判断, 先查前序任务实际状态, 不假设

**反例 (M3 误诊 #1)**: B3 hydration 路径 vs B4 区域 hreflang 路径差异, M3 推断"P0 阻塞", K3 12:04 拍板"不阻塞"

## 2. SOP-10 第 2 款 (K3 8/24 14:25 拍板 C)

> **上报拍板前先问"这条约束的原文适用范围是什么", 不替 K3 推断"红线=不动所有 src/"**

应用范围:

## 3. SOP-10 第 3 款 (K3 8/24 18:35 拍板)

> **上报拍板前先问"原数据/拍板来源 + 是不是真数据", 不推断"假证书号"/"无来源数字"/"未证实设备"/"SLA 承诺"/"占位符"/"MOCK 数据"**

应用范围:
- 任何 certNo / 证书号 / validUntil 类字段
- 任何 "15 年" / "1,000+ 客户" / "海德堡" / "HP Indigo" / "ISO 9001" / "FSC" 类数字
- 任何 "24h SLA" / "12 大行业" / "国际顶级" 类业务承诺
- 任何 "01 100 150 1234" / "C123456" / "FSC-C123456" / "XXXX" / "TBD" / "占位" 类模式

**先问 3 问**:
1. 原数据拍板来源 (K3 何时拍板? commit ID?)
2. 是不是真数据 (业务真实还是占位符?)
3. 当前 K3 拍板是"留"还是"撤"?

**反例 (M3 误诊 #3, 严重)**: 12 件事全判错, 实际是 K3 8/19 拍板的真实数据

## 4. SOP-10 第 4 款 (K3 8/24 18:42 + 19:03 拍板)

> **certNo / validUntil 等"可查询字段"全撤, 字段值改空字符串, 不留联系方式**

应用范围:
- 任何 certNo / 证书号 / validUntil / 有效期限 字段
- 任何 "Contact for details" / "詳詢客服" / "詳細はお問い合わせください" 联系方式
- 任何 "issuer" / "認證機構" 字段 (issuer 也可空)

**字段值策略**:
- 撤 certNo: 不留联系方式, 改空字符串 `''`
- 撤 validUntil: 改空字符串 `''`
- 撤 issuer: 改 `'—'` 或空字符串
- 保留 name + scope: 描述性文案不动

**反例**: K3 18:42 拍板"留联系方式", 19:03 拍板反转"不留联系方式", M3 没问"拍板反转"就推断"留联系方式" → 浪费 1 commit

## 5. SOP-10 第 5 款 (K3 8/24 19:03 拍板)

> **任何 user-facing 文本含 [text](url) Markdown 语法, 必须用 parseInlineLinks 工具解析, 禁止 <p>{text}</p> 直接渲染**

应用范围:
- about.tsx 3 渲染位置 (L794/L830/L851): 全部用 `parseInlineLinks()` 包裹
- 任何新 page.tsx/component 需渲染含 Markdown 语义的 user-facing 字段
- 数据源 (.ts/.json) 不强制 — 渲染层决定是否解析

**配套工具**: `src/utils/parseInlineLinks.tsx` (2.6KB, React 组件)
- 解析 `[text](url)` → `<Link>` (内部) / `<a>` (外部) / `<a target="_blank">` (外链自动)
- 排除 `![alt](url)` 图片
- 排除代码块

**反例 (F1-batch-3 之前)**: about.tsx L796 `<p>{adv.desc}</p>` 直渲染, desc 含 `[ISO 9001](https://...)` 显示为原文

## 6. SOP-10 第 6 款 (K3 8/24 20:02 拍板)

> **任何 UI 卡片含 3 行以上"占位字段" (issuer/certNo/validUntil), 字段值为空/—/占位符时, UI 层不展示该行**

应用范围:
- 任何 credentials / certifications / 资质 卡片
- 任何 "認證機構" / "證書編號" / "有效期限" 类 UI 行
- 任何含 {label, value} 结构的卡片

**UI 层策略** (F1-batch-6 4.2 方案 B 落地):
```tsx
cred.items
  .filter((item) => item.value && item.value !== '—' && item.value !== '-' && item.value !== 'N/A')
  .map((item, j) => <li>{item.label}: {item.value}</li>)
```

**反例 (F1-batch-5 之前)**: about.tsx L878-891 渲染 issuer/certNo/validUntil 3 行, 值是 `'—'` / `''` / `''` 仍展示空行

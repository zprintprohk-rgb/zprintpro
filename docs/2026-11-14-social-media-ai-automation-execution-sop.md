# ZprintPro 社媒获客 AI 自动化执行手册

**版本**：2026-11-14  
**定位**：配套《三语言站点社媒 × SEO／AEO／GEO × AI 内容自动化战略执行方案》的操作层 SOP  
**目标**：用低成本 AI 建立“真实素材生产—多平台定时发布—评论分级回复—WhatsApp 规格询价—订单回流”的完整流程，而不是用机器人批量骚扰目标客户  
**当前状态**：执行设计已完成；未注册账号、未连接 API、未部署 n8n、未启用定时发布或自动回复

## 数据来源与采用原则

**数据来源**：用户新增的《ZprintPro 社交媒体 AI 自动》附件、本轮已完成的网站公开页检查、前一份战略报告，以及已读取的 Google、TikTok、LinkedIn、YouTube、Pinterest、n8n 官方文档。附件中的第三方工具价格、模型价格、平台限额、最佳发布时间、粉丝与订单目标、响应时效和交期均未取得当前原始凭证，本手册**不作为事实采用**。所有发布频率、时间与预算均为可调整的资源建议，不是效果承诺。

# 一、先回答“我要怎么做”：最低可行增长系统

## 1.1 现在最值得做的不是铺十个平台，而是跑通一条链

ZprintPro 当前网站自然流量与询盘较少，不能只靠继续增加站内文章解决；需要社媒承担主动分发。但“这几天没有美国客户联系”只能说明当前观察窗口内没有可见询盘，不能直接证明美国市场无效或某个关键词失败。应先确认 GA4、GSC、WhatsApp 和邮箱是否有完整记录，再用统一口径比较各市场的会话、有效询价、报价和订单。

最小可行系统只包含五项：

1. **真实素材**：手机持续拍摄印刷、裁切、装订、模切、纸样、包装与文件检查，不让 AI 虚构工厂与客户。
2. **AI 改编**：DeepSeek 根据一个真实主题生成对应市场的脚本、字幕、帖子与回复建议；Kimi 决定优先做哪个产品和平台。
3. **定时发布**：先用平台原生排程或已审核的官方 API，保存实际发布 URL，不把“工作流运行成功”当作“帖子已发布”。
4. **互动分流**：评论和 inbound 私信由 AI 分类；低风险问题可模板回复，价格、MOQ、交期、投诉和订单问题必须进入人工。
5. **WhatsApp 承接**：自动带入产品、来源和规格字段，销售确认报价与承诺，结果回写内容系统。

这套流程能把“发帖”与“做生意”连接起来。若只执行前三项，会得到内容产量；只有执行到第五项，才知道哪个内容真正带来采购机会。

## 1.2 对附件方案的取舍

| 附件建议 | 本方案裁决 | 原因与替代做法 |
|---|---|---|
| Facebook、IG、TikTok 同时全量启动 | **缩小为三市场各自的 2–3 个主平台** | 香港优先 IG／Facebook，美国优先 LinkedIn／YouTube／Instagram，日本优先 X／LINE／YouTube；TikTok 作为真实短视频测试，不作为唯一获客来源 |
| 每日生成并发布 3–5 条 | **以真实素材供给决定频率** | 低质量日更会快速耗尽题材；先用一个主题多平台原生改编 |
| 固定各平台“最佳时间” | **只作为初始排程假设** | 账号没有历史数据时不存在已验证的 ZprintPro 最佳时间；后按实际受众活动调整 |
| ManyChat 自动回复所有评论／私信 | **低风险分级自动，高风险转人工** | 价格、交期、投诉和订单不宜由通用机器人直接回答；Meta 具体自动化能力上线前复核 |
| Phantombuster／Dripify 批量连接与私信 | **不采用自动批量外联** | 容易制造垃圾互动并违反平台真实互动要求；改为 AI 起草、人工选择与发送 |
| 自动报价与统一交期话术 | **不采用** | 当前产品页尚有 MOQ、价格与交期冲突；报价必须读取有效规格与事实表，并由人确认 |
| 客户开箱、评价、截图直接做内容 | **取得明确授权后使用** | 客户设计、个人资料、聊天截图与 Logo 都可能包含敏感或受版权保护内容 |
| 固定粉丝、流量、询盘和订单目标 | **先建基线再定目标** | 当前没有社媒后台与订单归因基线，不能编出可达成的增长率 |
| “零成本”启动 | **改为低现金成本、明确人力成本** | 拍摄、审校、回复、销售跟进、账号维护与自动化运维都消耗真实人力 |

## 1.3 自动化边界：哪些能全自动，哪些不能

| 工作 | 自动化等级 | 具体边界 |
|---|---|---|
| 关键词聚类、选题建议、内容日历初稿 | **可全自动** | 只进入内部草稿，不代表直接发布 |
| 视频脚本、字幕初稿、多语帖子与标签建议 | **可全自动生成** | 必须绑定真实素材与事实；日语和粤语需语言审校 |
| 模板剪辑、尺寸适配、字幕烧录、封面初稿 | **可条件自动** | 自动检查画面、音乐、字体与客户资料；最终预览由人确认 |
| 已审批内容的定时发布 | **可条件全自动** | 只用官方 API／原生排程；必须有账号授权、发布回执和失败队列 |
| 自己帖子下的正面评论致谢 | **可条件自动** | 不重复刷屏，不每次都塞链接，不涉及个案承诺 |
| 价格、MOQ、交期、材料性能、能否承接 | **AI 起草，人工或规则审批** | 只有完整有效事实与明确规格才可使用规则答案，否则收集规格后转人工 |
| 投诉、质量争议、退款、文件错误、订单异常 | **必须人工** | AI 只负责分类、摘要与优先级，不公开承认责任或提出赔偿 |
| inbound 私信的规格收集 | **可条件自动** | 明确身份、保存用途、退订方式；敏感文件转受控渠道 |
| 主动私信、评论别人帖子、批量加好友 | **不自动执行** | AI 可寻找公开企业线索和起草，人决定相关性并逐条发送 |
| WhatsApp 报价、交期承诺与订单变更 | **必须人工确认** | 自动化可生成报价草稿与提醒，不可擅自承诺 |
| 数据汇总与周报初稿 | **可全自动** | 结论必须能回到 GSC、GA4、平台、询价或订单记录 |

LinkedIn 的官方社区政策要求真实身份与真实机构信息，并禁止垃圾信息和人为制造互动，因此不把自动连接、自动点赞、批量评论和自动私信作为增长手段。[LinkedIn 社区政策](https://www.linkedin.com/legal/professional-community-policies) TikTok 公开发布需要应用、`video.publish` 权限和用户授权，未审核应用存在可见性限制；所以 TikTok 自动化必须等正式审批与测试，而不是用一个非官方机器人绕过。[TikTok Content Posting API](https://developers.tiktok.com/doc/content-posting-api-get-started/)

# 二、带钱词如何变成社媒获客，而不是只变成文章

## 2.1 内容与关键词的关系

社媒平台不是 Google 关键词排名的简单延伸。用户未必会在 TikTok 输入完整的“catalog printing china”，但会被“目录报价前必须确认的规格”吸引，再进入对应落地页。因此关键词在这里承担三项任务：确定选题、统一落地页、让视频标题和说明可被平台内搜索理解。Hashtag 只起辅助分类作用，不能替代清晰标题、画面和正文。

每个内容单元都要指定 `product_id`、`market`、`primary_keyword`、`primary_url`、`funnel_stage` 和 `conversion_event`。例如“small batch sticker printing”对应美国贴纸页，转化事件是提交贴纸尺寸、数量单位、材料与用途；“即日印刷”对应香港合格急件页，转化事件是提交文件状态、数量、需要日期和取货／配送地区。若落地页未通过事实验收，相关词只用于内部研究，不做公开推广。

## 2.2 第一批产品与内容组合

| 市场 | 优先产品／带钱词 | 社媒选题 | 目标平台 | 询价动作 |
|---|---|---|---|---|
| 香港 | 海報印刷、a2印刷、宣傳單張印刷、摺頁印刷 | 成品尺寸与出血、折页顺序、纸张与文件错误 | IG 轮播／Reels、Facebook、YouTube Shorts | WhatsApp 预填尺寸、数量、材质、文件状态、需要日期 |

| 香港 | 學校印刷、小冊子印刷、證書印刷 | 页数与装订、校对版本、学生资料与授权 | LinkedIn、Facebook、YouTube | 提交机构采购清单；不公开客户或学生资料 |

## 2.3 行业大词与带钱词的预算纪律

行业大词用于理解品牌与品类，不适合直接作为所有视频的主题。例如“香港印刷”可以由公司能力总览、工厂流程和品类枢纽承接；“海報印刷”适合产品演示；“A2 海報出血點設定”则适合高意图教程。英文的 `catalog printing china`、`catalogs printing china`、`china catalog printing` 是同一采购意图的变体，不应拆成三个内容团队或三个近重复落地页。

Kimi 每周将资源按“有效询价证据”重新分配，而不是按搜索量想象分配。若包装视频带来大量设计爱好者但没有规格完整的询价，应修改 CTA 和受众定位；若目录内容播放不高，却持续带来完整 RFQ，就应继续制作。没有订单基线时，先把“规格完整率、报价率、未成交原因”做可靠，再讨论扩大预算。

# 三、真实素材到定时视频：低成本内容生产线

## 3.1 每周一次拍摄，形成可持续素材库

AI 自动生成画面不能替代工厂真实素材。建议建立固定拍摄清单，每次拍摄同时留横屏与竖屏、远景与近景、无声环境与简短讲解。所有素材先进入 `asset_registry`，记录拍摄日期、产品、工序、作者、客户授权、可用市场和禁用范围。客户文件、Logo、地址、面单、聊天与个人信息默认不可公开，必须打码或换用自有示意文件。

| 拍摄主题 | 必拍镜头 | 可衍生内容 | 风险控制 |
|---|---|---|---|
| 印刷与调色 | 上纸、运转、颜色近景、检查样张 | 过程短片、CMYK 教学、色彩检查 | 不显示客户文件全页，不用机器品牌作未授权背书 |
| 裁切与模切 | 安全距离下的过程、刀模或成品边缘、尺寸对比 | 出血、模切线、贴纸与包装结构 | 遵守现场安全，不拍危险操作模仿挑战 |
| 装订与折页 | 封面与内页、折页顺序、书脊、翻页 | 小册子、目录、同人誌教程 | 页数与装订建议按真实产品能力确认 |
| 材料与工艺 | 纸样标签、纹理、弯折、不同角度反光 | 纸张、烫印、覆膜、可移材料对比 | 性能与环保声明必须有来源和测试条件 |
| 包装与出货 | 结构装配、内衬、装箱、防护、尺寸测量 | 包装 brief、打样与交付准备 | 隐藏地址、面单、客户名和订单号 |
| 文件检查 | 自有示例屏幕、错误／正确局部、检查清单 | 印前纠错、RFQ、下载清单 | 用明确标注的教学示意，不伪装成客户案例 |

素材文件名建议为 `YYYYMMDD_product_process_shot_locale_status.mp4`，例如 `20261116_catalog_binding_closeup_en_review.mp4`。`status` 只允许 `raw / cleared / review / approved / expired`；发布工作流只读取 `approved`。如果素材授权到期或被客户撤回，状态改为 `expired`，后续排程自动阻断，已发布内容由人评估下架。

## 3.2 视频生产的七个节点

1. **选题简报**：Kimi 指定市场、产品、采购问题、目标 URL 和转化事件。
2. **素材匹配**：DeepSeek 只从已批准素材中选择，不足时输出“需要补拍”，不生成假工厂替代。
3. **脚本与分镜**：每条只回答一个问题，明确开场画面、过程、结论和 CTA。
4. **粗剪与字幕**：初期用剪映／CapCut 模板；稳定后再考虑 FFmpeg 自动尺寸适配与字幕烧录。
5. **质量检查**：检查事实、语言、单位、版权、音乐、Logo、面单、文件内容、目标链接与视频可播放性。
6. **人工批准**：审批人看到最终画面和文案，不只批准脚本。
7. **排程与回执**：进入官方排程，保存平台 URL、发布时间、版本与活动 ID。

YouTube 官方上传接口支持 OAuth 后设置标题、说明、隐私状态与 `publishAt`，可作为后续定时发布通道。[YouTube videos.insert](https://developers.google.com/youtube/v3/docs/videos/insert) Shorts 使用方形或竖屏格式，并按当前官方时长与版权规则检查；有版权主张的长视频可能被屏蔽，所以配乐必须来自当前平台允许的授权库或自有权利素材。[YouTube Shorts 官方说明](https://support.google.com/youtube/answer/15424877?hl=en)

## 3.3 三条可直接拍摄的低风险视频脚本

### A. 美国：Catalog RFQ

- **开场画面**：两份报价简报，一份只有“catalog”，另一份包含完整规格。
- **字幕**：`A catalog quote needs more than a page count.`
- **中段画面**：依次展示尺寸、封面／内页、装订、数量、打样、目的地。
- **口播**：`Before comparing catalog printing quotes, make sure each supplier is pricing the same specification.`
- **结尾**：`Use the RFQ checklist, then request a quote based on your actual project.`
- **落地**：已修复 MOQ 与价格冲突的英文 catalog 页。

### B. 香港：小冊子跨頁檢查

- **開場畫面**：一張跨頁圖在装订位置的局部放大。
- **字幕**：`跨頁圖，唔好淨係睇 mon 上面啱唔啱。`
- **中段畫面**：展示页数、装订、书口与重要文字位置，使用教学示意文件。
- **口播**：`整小冊子之前，要同時睇頁數、裝訂同跨頁位置；重要文字唔好貼近裁切或裝訂位。`
- **結尾**：`帶埋尺寸、頁數、數量同需要日期，先整理規格再正式報價。`

### C. 日本：綴じ方の実物確認

- **开场画面**：两种实际可供应的冊子装订样本并排。
- **字幕**：`同じ冊子でも、綴じ方で確認点が変わります。`
- **中段画面**：表紙、本文、ノド与ページ構成；仅解释真实可见差异。
- **口播**：`入稿前に、綴じ方、ページ数、用紙、塗り足しをそろえて確認しましょう。`
- **结尾**：`詳しいチェックリストは、冊子印刷ガイドで確認できます。`

# 四、评论、私信与目标客户触达：把“自动回复”拆成风险等级

## 4.1 评论处理流程

平台通知或官方 API 收到评论后，DeepSeek 只做以下分类：`praise`（正面）、`product_question`（产品问题）、`quote`（价格）、`lead_time`（交期）、`capability`（能否制作）、`complaint`（投诉）、`spam`（垃圾）、`unclear`（不确定）。随后根据风险表决定动作。所有公开回复保存原评论、模型建议、实际回复、操作者与时间，便于抽查和纠错。

| 分类 | 自动动作 | 禁止动作 | 人工触发条件 |
|---|---|---|---|
| 正面评价 | 简短感谢；同一用户不重复营销 | 把一般赞美改写为公开客户证言 | 需要引用为案例或评价时 |
| 一般产品问题 | 从已批准 FAQ 回答，并附相关指南 | 猜测材料性能或兼容所有文件 | 问题超出 FAQ 或涉及具体项目 |
| 价格／MOQ | 回复“取决于规格”，收集尺寸、数量、材质与目的地 | 在未核实规格前给数字 | 规格齐全后由报价负责人处理 |
| 交期 | 说明需按文件校了、规格与目的地确认 | 自动承诺即日、固定工作日或到货日 | 所有具体日期与急件 |
| 能否制作 | 请求尺寸、数量、用途、文件状态 | 无条件回答“都能做” | 特殊工艺、包装结构与大批量 |
| 投诉／质量争议 | 仅做内部高优先级提醒 | 自动道歉认责、公开争论、自动赔偿 | 全部转人工 |
| 垃圾／仇恨／诈骗 | 按平台工具隐藏或报告，保留证据 | 用 AI 与对方争吵 | 威胁、法律或安全问题立即升级 |
| 不确定 | 不公开回复，进入人工队列 | 为追求回复率强行生成 | 全部 |

## 4.2 三语安全回复模板

**价格——英文**：`Thanks for your interest. Pricing depends on the size, quantity, material, finishing and delivery destination. Send those details through the quote link and we can review the specification for a formal quote.`

**价格——香港繁中**：`價錢要按尺寸、數量、紙材／工藝同配送地區計算。你可以經查詢連結一次過提供規格，我哋整理後再出正式報價。`

**价格——日文**：`価格は、サイズ、数量、用紙、加工、配送先などの仕様によって変わります。仕様相談フォームから詳細をお送りいただければ、内容を確認のうえ正式にお見積もりいたします。`

**交期——英文**：`Timing depends on the specification, file approval and destination. Share your required date and project details so the team can confirm what is feasible.`

**交期——香港繁中**：`實際時間要睇規格、檔案校了同配送安排。請提供需要日期同項目資料，由同事確認可行安排。`

**交期——日文**：`製造・配送の日程は、仕様、データ校了、配送先によって異なります。希望納期と仕様をお送りいただければ、担当者が対応可能な日程を確認いたします。`

以上模板只用于 **inbound 问题**，不能配置成对陌生用户的批量消息。正式启用前仍须由日语审校确认语气、术语和实际业务流程，模板本身不能绕过语言闸门。

## 4.3 主动获客：AI 找人，人决定是否接触

“联系目标客户”应拆成合规的账户制开发，而不是自动在他人帖子下留言。可由 AI 辅助建立公开企业候选清单：业务类型明确可能需要包装、目录、书刊或活动物料；有公开企业联系渠道；与当前产品和交付地区匹配；没有明显拒绝营销记录。不得购买来路不明个人名单、绕过平台限制抓取账号、批量添加好友或根据敏感个人属性定向。

建议优先四类企业任务，而不是泛泛找“所有美国小企业”：

- 正在推出或更新产品包装的电商品牌——提供包装 brief，不直接声称能降低成本。
- 有持续目录／出版物需求的企业或机构——提供 RFQ 与文件检查清单。
- 设计工作室、印刷经纪与活动供应商——讨论白标生产或文件协作的可能性，由人判断。
- 婚礼与文具相关商家——以真实喜帖／纸品样品和规格交流，不盗用他人设计图。

**LinkedIn 人工连接草稿**：`Hi {name} — I noticed your work on {specific_public_project}. We produce custom printed packaging and catalogues, and I put together a short RFQ checklist that may be useful when comparing specifications. No pitch needed; happy to share it if relevant.`

这只是一段**人工审核后的候选草稿**，不得自动发送，也不得虚构看过对方项目。如果 `{specific_public_project}` 没有真实公开来源，就删除该句。对方未回应时，不启动自动多轮私信；后续邮件或消息须符合适用法律、平台规则与对方退订选择。

# 五、WhatsApp 从“聊天工具”升级为可归因询价系统

## 5.1 每个入口都要带来源与规格

所有社媒简介、帖子、视频说明和落地页的 WhatsApp 链接，不只包含电话号码，还要包含 `content_id`、`campaign_id` 与产品信息。用户点击后看到其语言的规格模板，减少只发“Hi”或“Price?”造成的来回沟通。若用户来自某条贴纸视频，预填产品就是贴纸；若来自目录 RFQ，则显示目录所需字段，而不是通用“请告诉我们你的需求”。

建议保存以下事件：`social_post_published`、`outbound_click`、`landing_view`、`whatsapp_click`、`inquiry_started`、`qualified_inquiry`、`quote_sent`、`order_won`、`order_lost`。只有达到预先约定的规格完整度才算 `qualified_inquiry`。点击、聊天开始、报价和订单必须分开，不能用 WhatsApp 点击数冒充客户数。

## 5.2 可自动与不可自动的消息

| 场景 | 自动化动作 | 人工确认点 |
|---|---|---|
| 用户首次主动发消息 | 用相同语言回复并发送规格清单 | 无法识别产品或用户有复杂问题 |
| 用户已提交规格 | 检查缺项、生成内部摘要、分配产品负责人 | 是否可生产、价格、交期与配送 |
| 文件待检查 | 提供安全上传方式、建立文件检查任务 | 实际文件判断、修改建议与校了 |
| 报价草稿 | 根据已批准事实整理报价字段 | 最终价格、有效期、付款与条款 |
| 报价后跟进 | 在同意与频控范围内生成提醒草稿 | 是否发送、议价、变更与停止跟进 |
| 订单节点 | 读取真实订单状态并生成通知草稿 | 异常、延迟、赔偿与客户争议 |
| 营销订阅 | 保存同意、语言偏好和退订 | 模糊许可与历史名单导入 |

附件中的“24 小时、3 天、7 天自动跟进”和“2 小时回复”“5–7 天生产”不能直接上线。跟进时间应根据客户上下文、许可和销售负责人设置；交期与响应承诺必须有真实业务依据。WhatsApp Cloud API 的消息窗口、模板、费用及许可规则，上线前须重新核验当期官方文档；未通过前使用 WhatsApp Business 原生快捷回复与人工发送。

## 5.3 WhatsApp 欢迎与规格模板

**英文欢迎消息**：

# 六、n8n＋DeepSeek Harness：低成本可执行工作流

## 6.1 工作流一：每周内容生产

```text
人工选择已验证产品／关键词
→ 创建 content_brief
→ 读取 fact_registry 与 asset_registry 白名单
→ DeepSeek 生成脚本、帖子、字幕和平台版本
→ 事实／品牌／语言／版权／落地页自动检查
→ 不合格：fact_blocked 或 returned_for_edit
→ 合格：生成预览包
→ 人工审批最终视频与文案
→ 写入 ready_to_schedule
```

每周内容生产不应从“让模型随便想 30 条创意”开始，而应从真实素材、销售问题与重点词开始。简报必须指定不得使用的声明、允许引用的事实 ID 和目标 URL。没有有效素材时输出补拍清单；没有有效事实时删除数字，不允许模型补全。

## 6.2 工作流二：定时发布

```text
读取 approved 且到达排程时间的 content_item
→ 检查账号授权、平台格式、事实有效期与幂等键
→ 调用官方 API／或生成原生排程任务
→ 等待平台回执
→ 成功：保存 post_id、URL、published_at
→ 超时：先查询是否已发布，不立即重复提交
→ 失败：failed 队列＋错误分类＋人工提醒
```

TikTok、YouTube、LinkedIn、Pinterest 都有各自的授权与发布要求，不能使用同一套通用节点假设全部可用。Pinterest 需要商业账号、应用注册、试用访问审核和 OAuth；回调 URL 必须精确匹配。[Pinterest API 入门](https://developers.pinterest.com/docs/getting-started/introduction/) n8n 只负责编排，不会自动获得平台权限。自托管也意味着备份、升级、密钥、服务器可用性和安全维护都是实际成本。[n8n Hosting](https://docs.n8n.io/hosting/)

## 6.3 工作流三：评论与私信分流

```text
平台原生通知／官方 API 获取 inbound 互动
→ 去重并识别语言、市场、原帖和评论类型
→ DeepSeek 分类＋建议回复＋风险分
→ 低风险且已有批准模板：按平台能力回复或进入人工一键发送
→ 询价：发送规格链接／WhatsApp 入口
→ 价格、交期、投诉、订单：人工队列
→ 保存互动与后续 lead_id
```

上线初期建议**不自动公开回复**，先让 AI 生成建议、人工一键采用。经过抽查确认分类和语气稳定后，才考虑对“正面致谢”等最低风险类别自动处理。任何模型低置信度、负面评论、敏感话题或具体项目问题都直接转人工。不要在别人帖子下部署自动评论机器人，不把竞争对手受众批量导出后私信。

## 6.4 工作流四：每周经营复盘

```text
读取平台发布回执与原生数据
＋ GA4 UTM 落地会话与出站事件
＋ GSC 查询／页面数据
＋ WhatsApp 有效询价与规格完整率
＋ 报价、订单和未成交原因
→ DeepSeek 生成事实型周报与异常清单
→ Kimi 输出加码／修改／观察／停止决策
→ 生成下一周 brief，不自动扩大预算或频率
```

周报每个数字必须包含数据源、时间窗和口径。模型不得把缺失数据填成 0，也不得把无法取得的平台指标写成“无效果”。如果某条内容只有曝光、没有出站或询价，报告只陈述这一事实，不编造品牌提升。

## 6.5 最小字段与状态

| 对象 | 最低字段 |
|---|---|
| 内容简报 | `brief_id`、市场、语言、产品、关键词、采购问题、事实 ID、素材 ID、目标 URL、CTA、禁用声明 |
| 内容版本 | `content_id`、`version`、平台、正文、脚本、媒体 URL、审批人、审批时间 |
| 发布记录 | `publication_id`、账号、幂等键、排程时间、平台 post ID、发布 URL、回执、错误 |
| 互动记录 | 平台、原帖、评论／私信 ID、分类、风险、建议回复、实际动作、负责人 |
| 询价记录 | `lead_id`、UTM、`content_id`、产品、规格完整度、报价状态、订单状态、未成交原因 |

状态继续使用 `draft / fact_blocked / ready / approved / scheduled / published / failed`。任何绕过 `approved` 的 API 调用都应在程序层拒绝，而不是只靠提示词提醒。密钥与 token 放在受控环境变量或密钥管理中，禁止写入 Git、工作流导出、帖子、报告或模型提示词。

|---|---|---|---|---|

| Day 2 | 拍摄或整理真实素材，清除未授权客户资料 | 建立素材登记与缺拍清单 | 选择最容易解释的采购主题 | 素材 ID 与授权状态 |

## 7.2 第 2 周：跑通评论到 WhatsApp

第二周继续发布真实素材，同时启用 AI 评论分类与回复建议。每条价格、MOQ、交期问题都记录用户缺少哪些规格，检查 WhatsApp 预填是否减少来回问答。销售必须标记有效询价、已报价、未成交及原因；如果暂时无人回复评论或跟进 WhatsApp，应先解决负责人和通知机制，而不是继续增加发布量。

本周不做批量主动私信。可选择少量高度相关的公开企业候选，由 AI 生成个性化草稿，业务负责人核实公开项目和联系方式后逐条决定。任何没有真实个性化的模板不发送。

## 7.3 第 3 周：只扩大有中间证据的格式

根据前两周数据选择表现较好的内容主题。判断依据包括保存、完整观看、出站点击、规格完整询价和销售可用性，不只看粉丝。将同一真实主题改编为站内指南、短视频、轮播或 LinkedIn 文档；如果某格式制作成本高但没有中间证据，下周停止，而不是因为计划写了就继续。

此时可为 YouTube 或其他已通过权限测试的平台接入官方排程。Meta／TikTok／WhatsApp 的具体自动化仍需完成当期官方规则与账号权限复核。API 失败时保留人工原生发布，不让自动化阻塞正常业务。

## 7.4 第 4 周：形成第一版经营基线

月底输出三市场各自的：发布成功数、事实阻断数、内容主题、原生互动、UTM 会话、WhatsApp 点击、有效询价、报价、订单、未成交原因和人力投入。Kimi 决定下月保留哪些产品、平台和格式，DeepSeek 更新模板与字段，但不得自行把粉丝或询盘目标翻倍。

若没有任何有效询价，先逐段排查：内容是否面向采购者、落地页是否可信、CTA 是否明确、WhatsApp 是否可用、规格是否太复杂、销售是否跟进。不能把“没有订单”简单归因为发布不够多，也不能用购买粉丝或批量私信掩盖漏斗问题。

# 八、每周运营节奏与最低人工岗位

## 8.1 建议节奏

| 频率 | 人工工作 | AI／自动化工作 |
|---|---|---|
| 每日 | 查看高风险评论、私信与 WhatsApp；处理报价和订单；拍补充素材 | 分类互动、生成回复建议、检查发布回执、提醒异常 |
| 每周一次集中制作 | 拍摄与剪辑真实素材，审校最终视频和语言 | 生成选题初稿、脚本、字幕、平台版本与检查报告 |
| 每周复盘 | 销售确认有效询价与未成交原因，业务确认事实变更 | 汇总平台、GSC、GA4、WhatsApp 与订单数据 |
| 每月 | 决定平台与产品增减、预算和权限复核 | 更新关键词地图、到期事实提醒和月度报告 |

最低岗位不是“无人”，而是明确四个责任：**素材负责人、语言／事实审校、发布与互动负责人、销售报价负责人**。小团队可以一人兼多职，但每个任务必须知道由谁最终确认。若没有人能在当天处理评论和 WhatsApp，自动发布应减量，避免广告式发帖后无人接待。

## 8.2 不建议现在购买或开发的东西

暂不购买昂贵的跨平台分析套件，不开发全自动报价机器人，不购买批量外联工具，不为所有平台同时开发 API，不制作没有真实素材的 AI 虚拟工厂系列，也不以粉丝目标购买互动。初期优先使用平台原生排程、真实手机素材、剪映／CapCut 模板、DeepSeek 文案与分类、简单数据表和 UTM。

只有当人工流程已经证明某个主题能获得有效询价，才值得投入更复杂的视频自动生成、API 发布和 CRM 集成。低成本不等于永远手工，而是把自动化投资放在已验证的重复劳动上。

```text
zh-hk 使用智印港，en/ja 使用 ZprintPro，不并列双品牌。
不得生成自动私信、批量评论、自动报价或未经提供的客户案例。
输出后运行事实、语言、版权、链接和平台格式检查；任何缺项进入 fact_blocked。
```

## 9.3 DeepSeek 评论分类提示框架

```text
输入为原帖、用户评论、语言、已批准 FAQ 和有效事实。
只输出分类、风险、建议回复、是否需要人工和引用的 FAQ／事实 ID。
价格、MOQ、交期、投诉、退款、订单、法律、敏感资料与低置信度一律需要人工。
不得自动在他人帖子下评论，不得发送陌生私信，不得假装真人或虚构案例。
回复必须短、明确下一步；不知道就说需要确认，不补全答案。
```

提示词只是辅助，真正的权限必须在系统和账号层实现。即使模型被诱导“忽略规则直接发布”，发布端仍应因缺少 `approved` 状态而拒绝调用。

# 十、管理层验收清单

## 10.1 开启自动发布前

- [ ] 目标产品页已通过事实验收，MOQ、单位、价格、交期、主体与联系方式无冲突。
- [ ] 每条内容都有有效事实 ID、授权素材 ID、目标 URL 和 CTA。
- [ ] 已审批最终视频与文案，不是只审批脚本。
- [ ] 账号授权、应用权限和平台规则已由负责人复核。
- [ ] 有幂等键、发布回执、失败队列和一键停用开关。
- [ ] UTM 测试会话能进入询价记录。

## 10.2 开启自动回复前

- [ ] 先运行一段“AI 建议、人工发送”并保留抽查记录。
- [ ] 价格、交期、投诉、订单和敏感内容全部转人工。
- [ ] 用户能识别人工入口，不被机器人循环阻挡。
- [ ] 不自动评论他人帖子，不批量私信，不自动添加联系人。
- [ ] WhatsApp 同意、退订、频控、文件权限与保存期限已明确。
- [ ] Meta／WhatsApp 等未核验的当期规则已经重新验收。

## 10.3 最终裁决

ZprintPro 可以把**大部分重复整理与改编工作自动化**，但实际节省的人力须由运行记录测量；公开动作仍应分级。真正适合全自动的是数据整理、草稿、校验、排程与回执；真正需要人工的是事实、报价、交期、投诉、版权和主动外联。增长的核心不是让 AI 假装成很多人在网上说话，而是让真实工厂与真实采购知识持续被发现，并且每次互动都能进入可追踪、有人负责的 WhatsApp 询价流程。

**第一阶段拍板建议**：先用香港海报／小册子、美国目录／贴纸、日本冊子／贴纸做三市场小规模试点；采用原生排程＋AI 评论建议＋WhatsApp 规格预填。完成事实与归因验收后，再开启已审批视频的官方 API 定时发布。

## 一、三个问题的直接回答（Executive Answers）

1. **模型选型**：四个模型中，**GLM-5.3 对二级类目页/三级详情页的 UX/UI 设计落地能力最强**（有公开的前端盲测第一谱系 + 像素级视觉还原的官方能力声明 + 多模态视觉编码）。推荐组合：**GLM-5.3 做设计实现主笔 + Doubao Seed-Evolving 做交叉评审/Agent 流水线 + GLM-5.3-Flash / Seed 2.1-Turbo 做批量变体与成本压缩**。
2. **"松散感"根因**：不是内容少，而是**信息架构重复 + 视觉层级塌陷**——同一段卖点在页面上出现 4 次（Tabs 段 / 产品详情段 / 长文 SEO 段 / FAQ Q1-Q4），且转化信任信号被埋到页面最底部。解法是**结构重排**（去重 + 信任前置 + 双栏粘性报价轨），不是加更多内容。
3. **聊单客服**：**加，但不替代 WhatsApp**。加"AI 预筛 + 结构化留资"的网页聊天入口，把 WhatsApp 保留为人工聊单主通道；聊天数据写入 008 台账（src 参数），与归因闭环绑定，否则就是盲投。

## 三、现状诊断：为什么三级详情页"松散"（截图实证 6 病灶）

以 zh-hk 防水贴纸页（截图）为样本，红框冻结区之外的病灶：

1. **信息 4 次重复**：防水贴纸卖点同时出现在 ① Tabs"产品详情"段、② "产品详情"长段（材质对比/工艺表）、③ 底部无样式 SEO 长文、④ FAQ 手风琴 + 再下方的 Q1-Q4 纯文本。重复 = 用户滚动疲劳 = 感知松散，且稀释专业感。
2. **信任信号后置**：6 个信任图标（深圳自有工厂/即日交货/免费打样/品质保证/24小时支持）在页面**最底部**，而用户决策点在第一屏价格表旁。信任必须在报价旁边，不能在第 8 屏。
3. **表格是"内部规格书"样式**：蓝底白字表头的纯数据表，像 ERP 导出，不像高端 B2B 印刷目录。缺少材质实拍小图、克重可视化、应用场景缩略图。
4. **相关产品卡片的红色爆炸贴**（"热卖中·免费设计"星形贴）视觉噪音大，传递"打折店"而非"专业印刷伙伴"信号，与 hero 区已有的 1 个爆炸贴重复放大廉价感。
5. **长滚动无锚点**：从 tabs 到 footer 约 8 屏单列堆叠，无粘性导航、无"回到报价"悬浮条，B2B 买家滚到第 4 屏就流失，而报价 CTA 只在顶部。
6. **SEO 长文裸排**：底部大段无排版文字（**常见简称**、收单说明等）直接暴露给用户，应折叠进"采购指南"可展开区或转为结构化卡片。

**核心判断**：松散 ≠ 内容不足，= **结构无节奏 + 信任错配 + 转化锚点单一**。redesign 的目标是把"8 屏单列流水账"重排为"3 幕式专业目录页"。

## 四、重设计方案（红框冻结，仅动非冻结区）

### 4.1 冻结 / 改造分区（红线）

- **冻结（红框）**：顶栏（电话/邮箱/WhatsApp）+ Logo 搜索 + 主导航 + 面包屑、hero 左图 + 右栏（标题/描述/价格/参考价格表/批量折扣/WhatsApp 即时咨询按钮组）、信任徽章行（15年/30秒/免费重印/24-7）。**这些是已验证的转化栈，一字不动。**
- **改造（非冻结）**：Tabs 以下全部内容区。

### 4.2 三幕式结构重排

**第一幕 · 决策幕（第 2-3 屏，替换现 Tabs 段）**
- 左：内容主栏。右：**粘性报价轨**（sticky，滚动全程可见）= 缩略价格 + "30 秒报价" + WhatsApp 双 CTA。解决病灶 5。
- 信任条**上移**到本幕顶部（从页底搬来，6 图标重绘为线性 icon + 一句证据文案，如"15 年本地经验 · 服务 15,000+ 客户"改为"15 年 · ISO 12647 色彩管理"等可验证表述，遵守数据诚信红线）。解决病灶 2。

**第二幕 · 专业幕（第 4-6 屏，重排产品详情）**
- 材质对比从蓝头表格改为**对比卡片组**：每材质一卡（实拍小图 + 克重条 + 3 个适用场景 chip + 单价区间），卡片间留白按 8pt 网格。解决病灶 3。
- 工艺/印刷说明合并为**单一"工艺与品质"折叠面板**，默认展开首项，其余收起。去重：Tabs 段与长段只保留一处权威版本。解决病灶 1。

**第三幕 · 证据幕（第 7-8 屏，重构 SEO/FAQ/相关）**
- 相关产品卡片**移除爆炸贴**，改为干净图 + 一行卖点 + 价格；爆炸贴全站只保留 hero 1 处。解决病灶 4。
- FAQ 保留手风琴（带 FAQPage schema 不动），下方 Q1-Q4 纯文本**删除**（与手风琴重复），SEO 长文折叠进"采购指南（展开阅读）"。解决病灶 1、6。
- 页底保留品牌陈述 + 单一大 CTA（现状已有，保留）。

### 4.3 设计系统令牌（交给 GLM-5.3 的约束）

- 网格：8pt；栏宽：内容 8 列 + 报价轨 4 列（≥1024px），移动端报价轨变底部悬浮条。
- 色彩：品牌蓝 #2873F6 唯一强调色；红 #E5484D 仅用于 CTA 与 hero 徽章；正文灰阶 3 级；禁用第 3 个饱和色。
- 字体层级：H1 32/H2 24/H3 18/正文 15，行高 1.6；表格数字用 tabular-nums。
- 圆角 8px 统一、阴影 1 级（0 1px 2px rgba(0,0,0,.06)）；禁止多重阴影与渐变背景。
- 图片：材质/工艺实拍优先（现有 public/images/factory/* 22 figure 资产可复用），AI 图仅概念占位（遵守 K3 8/12 拍板：AI 图不上 PDP）。

### 4.4 SEO 安全约束（redesign 不得破坏）

- H1 唯一且含主关键词、FAQPage/Article/BreadcrumbList/Product schema、内链（≥7 锚点≥5 字）、12 铁律内容块全部保留；重排只改 DOM 结构不改文案与 schema（过门童 #14/#15 全绿才提交）。

## 五、聊单客服决策

**结论：加"AI 预筛 + 结构化留资"网页聊天，WhatsApp 保留为人工聊单主通道。**

**为什么加**：
1. 当前漏斗 = 点击 →（自由文本 WhatsApp）→ 人工聊单。B2B 前 3 轮对话 80% 是重复问答（MOQ/单价/交期/打样/材质），人工回复慢 = 丢单；AI 预筛可 24/7 秒回并**结构化采集**（数量/规格/交期/预算/用途），把 WhatsApp 聊单从"第 1 轮"推进到"第 3 轮"，人工只谈成交。
2. AI 引荐/对话式访客转化显著高于纯自然（行业数据：AI 引荐访客转化率约为自然搜索 5 倍量级，authoritytech 2026；口径：单源，作方向参考）。
3. 竞品（Sticker Mule 等）均有即时报价/聊天入口，我们只有浮动 WhatsApp 按钮，专业感差一档。

**为什么不替代 WhatsApp**：
- 现有 wa.me 深链已铺满全站（12 铁律 CTA 规范），替换 = 推翻已验证转化栈（且红框冻结区含 WhatsApp 按钮组）；
- 港/日/美客户对 WhatsApp/LINE 习惯不同，网页聊天做"入口与预筛"，WhatsApp/邮件做"成交与售后"，双通道互补。

**落地形态（最小可行）**：
- 右下角聊天浮窗 = 规则式 FAQ 快答（MOQ/价格/交期/打样，从 sku-seo-data 取数，不编造）+ "转人工"→ 带预填参数跳 wa.me（`?text=` 携带结构化需求）。
- 每次会话写 008 台账（src=webchat），与 WhatsApp（src=wa）并列归因。**前置条件**：008/GA4 归因解锁（R0 挂账项），否则先上 CF Web Analytics 事件做代理度量。
- 不接第三方 SaaS 聊天（数据出境 + 成本），用本地轻量组件 + 现有 LLM API。

**KPI**：聊天→留资率 ≥15%、留资→WhatsApp 接通率 ≥40%、PDP 询盘总量 +30%（9/30 校准）。

### 8.1 我与外部模型的分工边界（CEO 视角）

**最优组合（我的建议）**：视觉发散稿交给 GLM-5.3 出 2 版 → **我负责把稿子翻译成对本仓库的最小侵入改造**（只改非冻结区组件的 className/结构，不动数据与 schema）→ 我跑 build + verify + preview 部署 → K3 肉眼拍板。外部模型碰不到 main 分支，**我 = 集成者 + 质量闸门**，这正好避开"AI 直改大文件导致 9/3 事故"的坑。

### 8.2 三色调设计系统（以你给的色板为准，实测代码确认）

现有三色的真实用法（grep 实测，非推测）：

| 色 | Token | 实测用途 | 重设计后的语义角色（60-30-10） |
|---|---|---|---|
| 皇室藏青对角渐变 | `linear-gradient(165deg,#244780 0%,#1B3163 52%,#152649 100%)` | Footer / StatsBar / 即日急件 hero / 表格表头 / sharp-hook 图标 | **60% 权威面**：页脚、信任区、报价轨头、页内分段横幅——只承载"品牌与信任"，不承载操作 |
| 行动橙 | `#F87314`（hover `#EA580C`） | WhatsApp 浮标、CTA、徽章、强调下划线 | **10% 行动色**：每屏最多 1 个主 CTA + 价格强调；禁止橙色大面积铺底（现有产品卡爆炸贴降级为角标） |
| 功能蓝 | `#2873F5` | 链接、hover、选中态 | **30% 功能色**：导航激活、内链、tabs 选中——与 CTA 严格区分，用户一眼分辨"能点去哪"vs"现在就询价" |

**我会在动手前固化的 3 条硬规则**：
1. **渐变只用于"权威区"**（页脚/数据条/报价轨头/急件 hero），正文区一律白底 + 灰阶，杜绝现有"满屏粉蓝底"的松散感来源；
2. **橙色 CTA 单屏唯一**：hero 右栏 CTA 组（红框冻结，保留）之外，滚动区每幕最多 1 个橙色主按钮 + 1 个蓝色次按钮；
3. **无障碍修正**：白字压 #F87314 对比度约 3.2:1（仅大字号达标），小号按钮文字改用 `#EA580C`（已是你 hover 色，扶正即可，约 4.6:1 达标）——这是不改变观感的小修大赢。

### 8.3 我的执行序列（每步都有验证，不裸改）

1. **Token 化**：把三色 + 8pt 网格 + 圆角 8 + 单级阴影写进 `tailwind.config`/CSS 变量，替换散落的 arbitrary class（现状 123 处 `#F87314`、10 处渐变内联 style，grep 实测）——先收编再重排，避免改 1 处漏 10 处。
2. **试点 1 页**：防水贴纸 PDP（截图样本页），只动非冻结区，产出"三幕式"结构（§4.2）。改动全部组件级、可 feature-flag 回退。
3. **机器验收三件套**：`npm run build`（681 URLs 基线）+ 门童 #14/#15 全绿 + Lighthouse/CWV（LCP<2.5s）不劣化——任一不过不进 preview。
4. **preview 分支部署 + 截图对比**：对比重排前后同一视口的像素与层级，出 before/after 给你肉眼拍板（我提供对比图与 CRO 理由，你拍板，我不替你审美）。
5. **模板化扩散**：定型后由我把同一套结构套到 Top10 流量 PDP + 4 个二级类目页，攒批 1 push（§0.25 纪律）。
6. **聊天客服 MVP**（§5）：与 redesign 同 commit 攒批，src 埋点先行。

### 8.4 为什么这个分工对北极星最划算

- redesign 的唯一商业目标 = 把现有 imps 变成 clicks（CTR 0.54%→1.5%+），不是"更好看"。我全程用 GSC 数据验收（试点页 CTR 7 天对比），好看但 CTR 不涨 = 回滚，**用数据给美学投票**。
- 外部模型每轮有 API 成本与上下文损耗；我本机读写零边际成本，且已证明能守住"构建不挂、门童全绿、push 纪律"三条红线。**重设计的风险不在审美，在把站改挂——这恰好是我最能守住的部分。**

# ZprintPro Blog 内容质量对比与新标准（2026-07-02）

> **作者**: Mavis orchestrator
> **触发**: 用户反馈"Hermes 生成的 blog 文章质量与早期标准差距大，需要总结早期标准 + 更新 Skill"
> **核心结论**: 早期 2025-01-15 buying guides 已经做到 **800 字 zh-hk** 的优秀模板，但 Hermes 2026-06~07 的输出**字数翻倍但风格漂移**——从"教育指南"退化成"企业宣传册"。本文档总结差距、定义新标准、给出 Skill 修订方案。

## 1. 早期标准总结（2025-01-15 buying guides 模板）

**文件位置**: `F:\zprintpro-nextjs\src\data\buying-guides.ts`（9 篇，仍在生产部署）

### 1.1 早期 9 篇标准结构

每篇 buying guide 都遵循同一模板（5 段 + 引子 + FAQ + CTA）：

```
引子段 (80-100 字，1 段)
  → 介绍主题 + 行业口语化点睛（如"即香港行内讲嘅"）

H3 一、{主题 A 详解} (150-180 字)
  → 1 段引子 + 1 个 <table> 对照表（4-5 行 4-5 列）

H3 二、{主题 B 详解} (120-150 字)
  → 1 段引子 + 1 个 <ul> 项目列表（4-6 条）

H3 三、{主题 C 详解/工艺/设计} (120-150 字)
  → 1 段引子 + 1 个 <ol> 编号列表（4-5 条）

H3 四、{选购决策框架} (60-80 字)
  → bg-blue-50 框 + 4-5 条简短建议

H3 五、常見問題 (200-250 字)
  → bg-gray-50 框 + 4 个 Q/A（每条 50-80 字）

CTA 段 (50 字)
  → 3-4 个内链到产品页 + WhatsApp CTA
```

### 1.2 早期内容的核心特征

| 维度 | 早期标准 |
|---|---|
| **字数（zh-hk）** | 750-850 字（含表格内容；不算表格约 500 字） |
| **字数（en）** | 200-300 词 |
| **字数（ja）** | 150-250 词 |
| **结构层级** | 引子 + **5 个 H3**（不是 H2！） + FAQ + CTA |
| **Tone** | 教育型、行业口语化（如"即香港行内讲"、"3M 材质"） |
| **视角** | 第三人称客观描述（"贴纸决定耐用性..."）|
| **自报"我们"** | **0 次**！结尾 CTA 才出现 1 次"智印云" |
| **数据/数字** | 必须（克重、价格、规格、订单量） |
| **表格** | 1 个（材质/规格对比表，4-5 行） |
| **列表** | 2 个（一个 ul，一个 ol） |
| **FAQ** | 4 个 Q/A（具体到场景，不是空泛回答） |
| **内链** | 3-4 个到 `/product/xxx/` 产品页 |
| **CTA** | 1 段，3-4 个链接 + 1 个 WhatsApp |
| **Schema** | 由 page.tsx 自动注入（Article + BreadcrumbList + FAQPage） |

### 1.3 早期的"灵魂"特征（最难复制）

1. **行业口语化点睛**：用"即香港行内讲嘅"、"派街纸"、"中环商业区"、"3M 材质"等真实行业表达
2. **数据具体到规格**：不写"厚实"而写"400g"；不写"贵"而写"HK$150-300/100张"
3. **真实场景锚定**：用"餐厅派发"、"中环金融"、"设计师"等具象用户身份
4. **不做"我们最强"自吹**：通篇没有"我们的优势"、"我们的认证"、"我们提供"
5. **FAQ 答具体数字**：例如"贴喺玻璃、塑胶、金属表面，甚至短时间浸水都冇问题"——给读者可验证的事实

### 2.3 共性根因（Hermes prompt 没传达的）

1. **字数目标模糊**：prompt 说"≥600 字"但**没设上限**，导致 LLM 自由发挥到 2500+ 字
2. **缺少"反例"参考**：prompt 说"FAQ×4 + schema + 内链"，但**没禁止营销化用语**
3. **结构模板过简**：现有模板说"H3: 第一大主题..."，**没限定数量（5 个）和 H3 而非 H2**
4. **没有"灵魂特征"指引**：早期"行业口语化点睛"、"数据具体到规格"等特征**没有写进 Skill**
5. **自检清单缺位**：当前"易错检查清单"（§3）只查 git/sitemap，**没查内容质量**

## 4. 新标准定义（v3.5 内容质量基线 2026-07-02）

### 4.1 字数硬指标

| Locale | 下限 | 目标 | 上限 | 不达标处理 |
|---|---|---|---|---|
| **zh-hk** | 700 字 | **800 字** | 1000 字 | 低于 700 = 拒绝 push；超过 1000 = 重写精简 |
| **en** | 200 词 | **280 词** | 350 词 | 同上 |
| **ja** | 200 词 | **280 词** | 350 词 | 同上 |

> **字数计算方式**：`strip_tags(content)` 后中文字符数 / 英文 + 日文词数（用 `len(text.split())`）。可用 `node scripts/blog-content-engine.js` 自动验证（脚本待写）。

### 4.2 8 段结构模板（必须按顺序）

```
[1] 引子段        (60-100 字 zh-hk)
   → 行业口语化点睛 + 主题引入
   → 不出现"在本文中我们将..."、"本指南..."

[2] H3 一、{对比/规格}  (150-180 字 + 1 table)
   → 1 个 <table> 4-5 行 4-5 列
   → 列名必须是材质/规格/特性/适用/价格/克重之一

[3] H3 二、{工艺/选项} (120-150 字 + 1 ul)
   → 4-6 条简短工艺/选项说明

[4] H3 三、{设计/细节} (120-150 字 + 1 ol)
   → 4-5 条编号建议或注意事项

[5] H3 四、{选购决策} (60-80 字 + bg-blue-50 框)
   → 4-5 条按场景（预算/品质/规模/合规）建议
   → 框内允许 1 次"智印云"提示（"智印云选购建议"）

[6] H3 五、常見問題  (200-250 字 + bg-gray-50 框 + 4 Q/A)
   → 每个 Q 必须是客户真实问题
   → 每个 A 必须有具体数字或场景（不空泛）

[7] CTA 段 (40-60 字)
   → 3-4 个内链到产品页
   → 1 个 WhatsApp / Quote 链接
   → 允许出现 1 次"智印云"

[8] (隐式) Schema 由 page.tsx 自动注入
   → 不需要在 HTML 里手写 JSON-LD
```

### 4.3 Tone & Style 6 条禁忌（违反任一 = 重写）

| # | 禁忌 | 反例（Hermes 现状） | 正确写法 |
|---|---|---|---|
| 1 | **自报"我们优势"段落** | "智印云的优势：FDA 认证 + FSC 认证 + ISO 9001..." | 删除；用 H3 四、选购决策 bg-blue-50 框替代 |
| 2 | **罗列认证清单** | "FDA 21 CFR / EU 10/2011 / FSC / ISO 9001 / RoHS" | 除非客户明确问，否则只提 1 个最相关的认证 |
| 3 | **写公司内部流程** | "订购流程：1. 客户咨询 → 2. 需求确认 → ..." | 删除；客户不关心你内部怎么流转 |
| 4 | **泛泛 FAQ** | "Q: 食品包装多少钱 → A: 印量越大单价越低" | 必须给具体数字或场景（如"1000 个约 HK$3-5/个"） |
| 5 | **过度修辞形容词** | "完美印刷效果"、"极致的视觉享受" | 删除；用数字和场景替代 |
| 6 | **缺失对照表** | 全部用 <ul> 列材质 | 材质/规格/价格对比必须用 <table> |

### 4.4 灵魂特征 4 条（必须保留）

1. **行业口语化点睛**：每篇引子段必须出现 1 次类似"即香港行内讲"、"派街纸"、"中环"、"设计师最爱"等行业表达
2. **数据具体到规格**：所有"质量"、"耐用"、"价格"必须带具体数字（克重、HK$、毫米、年限）
3. **真实场景锚定**：FAQ 必须提到具体身份（"餐厅"、"设计师"、"中环金融"、"活动派发"）
4. **客户视角**：所有建议从"客户该怎么选"出发，不从"我们能做什么"出发
